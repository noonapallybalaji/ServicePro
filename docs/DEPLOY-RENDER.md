# Deploy a test copy on Render (free plan)

This puts the whole of ServicePro online for testing: the API, its PostgreSQL database, the
customer website, the admin app and the technician app. It uses Render's free plan, so it is
**for trying things out, not for real customers**.

## What the free plan means

| | What happens | What to do about it |
|---|---|---|
| API sleeps | After 15 minutes without visitors the API stops. The next request waits about a minute while it starts. | Expected. Open the site a minute before a demo. |
| Background work pauses while asleep | Offer timeouts, WhatsApp/SMS sending and rating requests run only while the API is awake. | Expected for testing. |
| Database expires | Free PostgreSQL is deleted 30 days after creation (14 days' grace to upgrade). | Treat all data as throwaway. Upgrade the database plan to keep it. |
| Photos are lost | Job photos are saved on the API's disk, which is wiped on every restart or deploy. | Fine for tests. For real use, move to object storage (a code change). |
| Sign-in codes on screen | There is no SMS/WhatsApp provider yet, so test mode shows codes on screen to anyone. | **Never** let real customers use this deployment. |

Render changes its free-plan terms from time to time; check [render.com/docs/free](https://render.com/docs/free).

## 1. Create the services

1. Push the branch to GitHub (Render deploys from a repository).
2. In Render: **New > Blueprint**, connect the repository, choose the branch. Render reads `render.yaml` and lists 1 database and 4 services.
3. It asks for the two values that are deliberately not in the file:
   - `Seed__OwnerEmail`: the email you will sign in to the admin app with.
   - `Seed__OwnerPassword`: a new, strong password (not the demo password from the repo: the API refuses to start with that one).
4. Click **Apply**. The first build of the API takes several minutes.

`Auth__SigningKey` is generated by Render. Nothing secret is stored in the repository.

## 2. Check the service addresses

Render names each service `<name>.onrender.com`. If a name was already taken, Render adds a
suffix (for example `servicepro-api-x1y2.onrender.com`). Then fix the addresses that point at
each other:

| Where | Setting | Must be |
|---|---|---|
| servicepro-site, servicepro-admin, servicepro-tech > Redirects/Rewrites | `/api/*` (and `/hubs/*`) destination | the real API address + `/api/*` (`/hubs/*`) |
| servicepro-site > Environment | `VITE_SITE_URL` | the real site address (then redeploy the site) |
| servicepro-api > Environment | `Notifications__PublicSiteUrl` | the real site address |

## 3. Try it

- **Health:** `https://<api>.onrender.com/health/ready` returns 200 once the database is ready.
- **Admin:** open the admin site and sign in with the owner email and password from step 1. Demo technicians, customers and jobs are already there.
- **Technician app:** sign in with a demo technician's phone, for example `9876500001` (Ravi Kumar). The code is shown on screen in test mode.
- **Customer site:** book a repair; the code is shown on screen.
- **Live updates** in the admin may fall back from WebSockets to polling through Render's rewrite. That is fine.

## 4. Before anyone real uses it

Do all of these, or use a paid setup instead:

1. Remove `Auth__TestMode` and `Auth__ExposeOtpInResponse` (the API then refuses to show codes) and connect SMS or WhatsApp (`apps/api/public.env.example`).
2. Set `Database__SeedDemoData` to `false` on a fresh database.
3. Move to a paid database plan (backups, no expiry) and a paid API instance (no sleeping).
4. Move photo storage off the server's disk.
5. Fill in the legal details and payment keys (see `docs/CUSTOMER-JOURNEY-GAPS.md`).

## How the pieces fit

- The three websites are static files. Each forwards `/api/*` (and `/hubs/*` for live updates) to the API. To the browser, every app talks to its own address, so sign-in cookies stay first-party.
- The API runs from `apps/api/Dockerfile`. It migrates the database on start, and refuses to start with unsafe settings such as the repo's demo password, the development signing key, or codes on screen without test mode.
- Rate limits use the visitor's real IP from `CF-Connecting-IP`. Render's Cloudflare edge sets it on every request (`Network__TrustClientIpHeader`). Never set that option where the API can be reached directly.
